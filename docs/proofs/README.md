# Proofs

A proof is a claim this project makes about the real world, recorded as evidence rather
than asserted. It exists because some claims cannot be closed by a test: a unit test
proves a function classifies two strings correctly, and says nothing about whether those
strings ever arrive from a live desktop with a human in front of it.

Everything in this directory is generated. Each artifact names the script that produced
it and the environment it was produced in, because a proof that does not say which
desktop it measured is a proof that will eventually be wrong without anyone noticing.

| Proof | Generated by | Claim |
|---|---|---|
| `keystrokes-reach-a-field-with-no-way-in.md` — **claim does not hold** | `scripts/prove-keystrokes-live.py` | A field that reads back and refuses every accessible write can be typed into with synthetic keystrokes, and the field afterwards says what the service claimed it would. |

The keystroke proof was recorded against Discord on a live GNOME desktop and the run
FAILED, which is the artifact's whole value: the tier typed one character and yielded to
a person who was not there. Synthetic keystrokes reset the display server's idle timer —
the only clock the presence watch has — and the tier had already raised the target window
to take focus, so its own first key satisfied both halves of the takeover test. Verified
in isolation: 88 seconds of real idle, one synthetic Shift, idle reads 101ms. No unit
test could see this; the fakes that stand in for the keyboard do not feed the idle
counter. The fix is tracked as its own issue, and the artifact stays failing until a
re-run on a live desktop says otherwise.

### which-credential-the-voice-lane-accepts

The voice lane can be handed either kind of OpenAI credential: a token minted by
signing in with a ChatGPT account, or a platform API key. Which of them
OpenAI's speech endpoint actually accepts decides whether "sign in with your
ChatGPT account" is enough for the product to have a mouth and ears.
`scripts/prove-voice-credential.mjs` answers it by spending each credential the
machine holds on one real request, and writes
`which-credential-the-voice-lane-accepts.md`.

Deposited 2026-08-04, from a machine holding a real ChatGPT device-flow token.
The verdict reads THE CLAIM DOES NOT HOLD, and one nuance in the recorded
response is worth naming: the refusal was `429 insufficient_quota`, not
`401 invalid credential`. The endpoint authenticated the ChatGPT token and then
refused on billing, because the account it maps to holds no platform API
credits. So the mechanism works and the wallet does not, and for the product
the two failures look the same: a person who signed in with ChatGPT alone must
be told, in the UI, that voice needs one more thing. The pasted-key path is
load-bearing, and `resolveVoiceCredential` keeps carrying the kind, because a
billing refusal is the one kind of no that can turn into a yes without a code
change.

## Rules

**Never hand-write one.** An artifact edited by hand is a claim again, which is the thing
a proof was supposed to replace.

**A failed run is still an artifact.** The scripts write what they found and exit
non-zero. Deleting an unflattering result and re-running until it passes turns the
directory into a collection of lucky moments.

**Never fill in a measurement that was not taken.** Where a comparison could not be run,
the artifact says so and gives the reason. An invented number is worse than a gap,
because a gap is visible.

**Re-run rather than trust.** These age silently — a toolkit update can change what the
accessibility bus reports without changing a line of this repository. An artifact is
evidence about the day it was written.
