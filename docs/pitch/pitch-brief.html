A desktop agent platform for everyone who isn't a programmer — built on Mastra Code

Factory proved that Mastra Code can carry a vertical product for developers. This is the second proof point — the same architecture, aimed at the far larger market of people who want an agent working their computer as them: small businesses, sales reps, operators, power users.

Prepared by Jamie (CodingButter)  ·  August 2026  ·  Working title: Computer Controls

The opportunity

Every agent product on the market today either lives in a browser tab, or drives a desktop by screenshots and coordinates — blind clicking, no consent model, no record of what was done. Meanwhile the people who would pay most for a working assistant — a sales rep clearing a CRM backlog, a small-business owner answering invoices, an operator living in three desktop apps — are underserved enough that a hardware dongle promising a "second user" just raised venture funding. The demand is proven. The approach on offer is still blind.

We have spent the last month building the missing layer: a semantic desktop control service that lets an agent see and operate real applications through the accessibility tree — by meaning, not pixels — behind a consent model that makes "acting as you" provable and bounded.

The pitch to a business owner is not what the agent can do. It is what the agent provably cannot.

The pattern is already proven — by us, on your stack

Factory is a Node service that drives headless Mastra Code sessions, with a web board on top. This product is the same skeleton with a different day job: sessions that operate the desktop instead of a repository. Nothing about the architecture is speculative — this product was built by Factory itself.

What ships

One .deb, the Plex model: install it, and your machine gains a resident assistant reachable from any browser — including your phone, paired by QR code over your own network. No cloud account required to function; the daemon deliberately owns no relay, no tunnel, no identity provider.

Dashboard & first clientLocal web app (PWA) — setup, settings, model packs, the audit feed, QR pairing

The desktop layer also ships standalone as a Mastra Code plugin — so every existing Mastra Code user gains desktop control, and the full product is the packaged experience of the same components.

The security layer nobody else has productized

GuaranteeMechanism (shipped & tested)
Bounded by constructionTools outside the granted scope do not exist to the model — no prompt can invoke a tool the agent was never handed.
The person outranks the agentPresence detection: a human touching the machine takes any field back mid-word, and the agent cannot re-take it.
Nothing leaves unapprovedA send gate: composing is not sending. Committing anything out of the machine requires a service-side attestation the agent cannot forge, judged against criteria the agent cannot author.
Provable recordAn audit log of every action — who, where, what class, which argument won — that never contains what was read or typed.
Secrets stay secretRedaction at egress; password fields are unreadable by design, even to the proof system.

The market has already voted — the competition just can't see

Violoop ("give your computer a second user") is a venture-funded hardware dongle — HDMI capture in, USB keyboard out, an 8B vision model in between — that drives any PC by reading pixels and emitting keystrokes, with a phone app to approve risky actions. A funded competitor selling the same promise is the strongest market validation we could ask for. It is also, architecturally, the thing our opportunity section indicts:

Violoop (hardware, pixels)This product (software, semantics)
How it seesScreenshots through an HDMI cable; a vision model guesses what is on screen.The accessibility tree: real elements with real roles, states and values — the same truth a screen reader gets.
How it actsA fake USB keyboard typing at whatever has focus — blind by construction.Addressed, verified actions on named elements; every write is read back and proven, or reported as a failure.

What it costs to shipA hardware BOM, a supply chain, one device per computer.An apt install — and a fleet of them for a small business is a config file, not a purchase order.
What it grows intoA closed appliance.Every Mastra Code plugin, plus a curated registry — a platform.

The honest concession: a keyboard dongle works on a locked screen and on any OS, today. That is real. It is also exactly the trade — universality bought with blindness — that stops being acceptable the moment the agent acts as you in front of a customer.

The platform question, answered before it's asked

The proof of concept runs on Linux. The platform-specific code is 2,442 lines of 13,800 — quarantined in a backends directory with zero accessibility imports leaking outside it (verified, not asserted). Everything that makes this product the product — the consent ceiling, attestations, the send gate, the audit log, redaction, the protocol, the entire TypeScript runtime layer — is platform-neutral. Windows is a backend port onto UI Automation, the richest accessibility API of the three and the one Narrator rides. macOS is a port onto the API that powers VoiceOver, where the OS's own per-app accessibility permission becomes free consent UX. The architectural bet underneath: accessibility trees are the one interface every OS is legally obligated to keep working. Screen readers must function; pixels carry no such guarantee.

The platform flywheel

  • Every Mastra Code plugin works here by default. The community's plugins — existing and future — become product capabilities without us building them. The product becomes multiple products.
  • A curated, approved-plugin registry sits on top for the commercial audience — the security posture demands review, and review becomes a quality bar, the way an app store is.
  • Every product user is a platform user. A second vertical on Mastra Code turns it from a tool with one product into a platform with a portfolio — and this vertical reaches a market the developer tools never will.

What exists today vs. what remains

Built and gated

The desktop daemon (protocol, security model, live proofs). The Mastra Code plugin (tools, scope-based tool minting, model-tier selection by scope). The Factory pipeline that built both.

To build

The client: dashboard, QR pairing, packaging (.deb + session service), the approved-plugin registry. The hard problems underneath — sessions, packs, memory, plugins — are already solved by Mastra Code.

The ask

  • Alignment on building this as a new product bucket on Mastra Code — the second vertical, with a dedicated owner.
  • Blessing rather than permission: the packages this rides (@mastra/core, @mastra/code-sdk, mastracode) are Apache-2.0, and Mastra's own licensing page explicitly welcomes commercial applications built on the stack. This could ship independently — it is being brought inside because it belongs inside.
  • Nothing else. The pattern is proven, the foundation is shipped, and the team that built it is already here.
